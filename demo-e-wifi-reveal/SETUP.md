# Demo E — Wi-Fi reveal setup

The code in this folder is the two things you *show*: the join QR
(`assets/wifi.png`, regenerated by `generate_assets.py` from `shared/config.py`)
and the captive-portal reveal page (`portal.html`). The access point itself is
infrastructure you stand up — deliberately, no interception is built here.

## What the QR contains

Standard `WIFI:` join credentials for **your own** AP, e.g.:

```
WIFI:T:WPA;S:Conference_Free_WiFi;P:letmein-demo-2026;;
```

Edit the SSID / password in `shared/config.py` (`DEMO_E`) and re-run
`python generate_assets.py`.

## Minimal safe AP + captive portal

1. Bring up an AP with the SSID/password from the config. A phone hotspot, a
   travel router, or `hostapd` + `dnsmasq` on a laptop all work.
2. Point the captive-portal detection URLs at `portal.html`. The easy path:
   run any static file server on the AP host and have `dnsmasq` resolve
   everything to it, so the phone's captive check (`captive.apple.com`,
   `connectivitycheck.gstatic.com`, etc.) lands on the reveal page.

   ```
   python3 -m http.server 80   # serve portal.html as index, from this folder
   ```

3. **Stop there.** Do not add a proxy, DNS logger, or packet capture. The reveal
   page makes the point; building interception would cross the line the talk is
   warning about.

## Rehearse on the real venue network

Captive portals and conference Wi-Fi are where live demos die. Test the
auto-join prompt and the redirect to `portal.html` on the actual venue setup
before you're on stage.
